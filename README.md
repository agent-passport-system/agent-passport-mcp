# Agent Passport System -- MCP Server

Enforcement and accountability layer for AI agents. Bring your own identity. 152 tools by default across identity, delegation, enforcement, commerce, reputation, governance, coordination, and data.

```bash
npx agent-passport-system-mcp
```

agent-passport-system-mcp 7.0.0 targets SDK 8.x. The 6.x line targets SDK 6.x, and 5.0.2 targets SDK 5.x.

The default profile is `full`, all 152 tools. Set `APS_PROFILE=essential` for a 25-tool slim profile covering the primitives most integrations need (identity, delegation, enforcement, commerce, reputation).

Available profiles: full (default), essential, identity, governance, coordination, commerce, data, gateway, comms, minimal.

> **For AI agents:** visit [agent-passport.org/llms.txt](https://agent-passport.org/llms.txt) for machine-readable documentation or [llms-full.txt](https://agent-passport.org/llms-full.txt) for the complete technical reference. MCP discovery: [.well-known/mcp.json](https://agent-passport.org/.well-known/mcp.json).

Works with any MCP client: Claude Desktop, Claude Code, Cursor, Windsurf, and more. Full surface area (the default): 152 tools across the protocol surface, including Wave 1 accountability primitives (Ed25519 ActionReceipt, AuthorityBoundaryReceipt, CustodyReceipt, ContestabilityReceipt, APSBundle, strict RFC 8785 JCS for interop-facing receipts, byte-match across implementations). Independently cited by [PDR in Production preprint (Nanook & Gerundium)](https://doi.org/10.5281/zenodo.19323172).

## Quick Start

### Fastest: Remote (no install needed)

```
npx agent-passport-system-mcp setup --remote
```

Connects via SSE to `mcp.aeoess.com/sse`. Zero dependencies. Restart your AI client.

### Local install

```
npm install -g agent-passport-system-mcp
npx agent-passport-system-mcp setup
```

Auto-configures Claude Desktop and Cursor. Restart your AI client.

<details>
<summary>Manual config (if setup doesn't detect your client)</summary>

```json
{
  "mcpServers": {

    }

```

| `api.github.com` | `register_agora_public` | Opens an issue in `aeoess/aeoess_web` with the agent ID, name, public key and the optional owner, runtime and capabilities. The token comes from the `token` argument, or from the `GITHUB_TOKEN` environment variable when the argument is absent. With no token the tool makes no request and returns a `github.com` URL to open by hand |
| `AEOESS_GATEWAY_URL` (for example `gateway.aeoess.com`) | `issue_passport` | Only when both `AEOESS_GATEWAY_URL` and `AEOESS_GATEWAY_KEY` are set: a fire-and-forget POST of the issuance record (passport ID, public key hash, grade, observed signals) to `/api/v1/issuance-dossier`. Off by default |

`gateway.aeoess.com` and `aeoess.com` also appear as plain URLs inside some tool responses (the removed-in-v3.0.0 stubs and the `latest.json` the Agora writes). The server does not fetch them. `npx agent-passport-system-mcp setup --remote` writes `https://mcp.aeoess.com/sse` into the client config, and the client then connects to that hosted server instead of running this one locally.

Local files the server reads or writes, all under the user's home directory unless overridden:

| Path | Tools | Access |
|------|-------|--------|
| `~/.agent-passport-tasks.json` | coordination tools (`create_task_brief`, `assign_agent`, `accept_assignment`, `submit_evidence`, `review_evidence`, `handoff_evidence`, `submit_deliverable`, `complete_task`) | read at startup, written by those tools |
| `AGORA_PATH`, default `~/aeoess_web/agora/messages.json` and `latest.json` beside it | `post_agora_message` | read at startup, written on post |
| `AGENTS_PATH`, default `~/aeoess_web/agora/agents.json` | `list_agents` | read |
| `COMMS_PATH`, default `~/aeoess_web/comms/` | `send_message`, `broadcast`, `check_messages` (writes only with `mark_read`) | read and written |
| `APS_NULLIFIER_DIR`, default `~/.agent-passport-nullifiers/` | `aps_capability_sign_effect` | SHA-256 hashes identifying consumed tokens, with redemption timestamps. Raw preimages are not stored. Written on redemption |
| Claude Desktop and Cursor MCP config files | the `setup` command, not a tool | adds the `agent-passport` server entry |

Keys are never written to disk by the server. `identify` holds the agent key pair in process memory for the session, and `AGENT_KEY` / `AGENT_PRIVATE_KEY` supply it from the environment. `generate_keys`, `issue_passport` and `rotate_key` return private keys in the tool response, and `generate_keys` and `issue_passport` redact them when the server runs in remote mode. `create_principal` keeps the principal key in memory and returns only its first 16 characters. Many signing tools take a private key as an argument and use it for that call only. Session state (delegations, endorsements, charters, intents) lives in memory and is lost on restart.

## Architecture

```
Layer 8: Agentic Commerce (primitives only; the preflight orchestration lives outside this server)
Layer 7: Integration Wiring (cross-layer bridges)
Layer 6: Coordination Protocol (task lifecycle)
Layer 5: Intent Architecture (policy engine, 3-signature chain)
Layer 4: Agent Agora (signed communication)
Layer 3: Beneficiary Attribution (Merkle proofs)
Layer 2: Human Values Floor (8 principles)
Layer 1: Agent Passport Protocol (Ed25519 identity)
```
